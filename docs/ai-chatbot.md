# AI 챗봇 요구사항 (쿠키 도우미)

화면 오른쪽 아래에서 언제든 열 수 있는 RAG 기반 챗봇입니다. CS 개념 질문에 답하고, 나의쿠키 사용법도 안내해요. 답변 모델은 Gemini 무료 등급이며, 홈서버 `.env`에 `GEMINI_API_KEY`가 이미 있습니다.

## 1. 목표와 범위

| 구분 | 내용 |
| --- | --- |
| 목표 | ① 모르는 개념을 물으면 답한다 ② 서비스 사용법을 정확히 안내한다 ③ 답이 어디서 왔는지 보여 줘서 믿을 수 있게 한다 |
| 1차 범위 | 오른쪽 아래 챗봇, 학습 문서와 서비스 안내 검색(RAG), 출처 표시, 근거가 약하면 일반 지식으로 답하며 표시, 요청 한도, 정확도 평가 |
| 1차 제외 | 내 계정 정보 답변(내 등급, 내 오답), 스트리밍 응답, 대화 기록 서버 저장, 음성 |
| 2차 후보 | 스트리밍(SSE), 문제 화면에서 "이 문제 물어보기", 내 오답 기반 추천, OpenAI로 모델 전환 |

## 3. 화면 (챗봇 모양)

### 3-1. 열기 버튼
- 오른쪽 아래 고정, 지름 56px 원형, 쿠키 아이콘. 바깥 여백 16px, 모바일은 하단 메뉴와 겹치지 않게 위로 올림
- 처음 방문한 사람에게만 말풍선 한 번 표시: "궁금한 게 있으면 물어보세요". 닫으면 다시 띄우지 않음(브라우저에 기억)
- 다른 고정 요소(오류 신고 버튼, 알림)와 겹치지 않는지 확인

### 3-2. 대화 창
- PC: 오른쪽 아래에 너비 380px, 높이 최대 600px 패널. 모바일(640px 미만): 전체 화면
- 머리: 이름 "쿠키 도우미", 새 대화, 닫기. 이름 아래 한 줄 안내 "개인정보는 입력하지 마세요"
- 첫 화면: 인사 한 줄 + 추천 질문 칩 4개(예: "트랜잭션 격리 수준이 뭐야?", "등급은 어떻게 올라가?", "대결은 어떻게 해?", "오늘 뭐부터 공부할까?")
- 입력: 최대 500자, Enter 전송, Shift+Enter 줄바꿈, 남은 오늘 질문 수 표시
- 답변 중: "자료를 찾는 중", "답을 쓰는 중" 상태 표시. 30초 넘으면 시간 초과 안내

### 3-3. 답변 한 개의 모양
- 본문: 마크다운(굵게, 목록, 코드, 표) 렌더링. HTML은 막아 XSS 방지
- **근거 배지** (가장 중요)
  - 🟢 `학습 자료 기반`: 검색한 자료로 답함
  - 🟡 `일반 지식`: 자료에 충분한 근거가 없어 모델 지식으로 답함. "틀릴 수 있어요" 문구 함께 표시
- **출처 칩**: `[1] 트랜잭션 격리 수준`처럼 문서 제목. 누르면 그 학습 페이지나 메뉴로 이동. 본문 속 `[1]` 표시와 번호가 같다
- 아래에 👍 👎. 👎를 누르면 "틀림, 부족함, 관련 없음" 중 하나를 고를 수 있음

### 3-4. 말투와 접근성
- 말투: 존댓말(해요체). 옛 고양이 반말("냥")은 쓰지 않는다
- 키보드로 열기, 닫기(Esc), 전송 가능. 새 답변은 `aria-live`로 읽힌다
- 색은 디자인 시스템 토큰을 쓰고 다크 모드를 지원한다

### 4-1. 질문 범위 판정과 클라이언트 응답

오른쪽 쿠키 도우미는 현재 입력한 질문에서 **사용자가 받고 싶은 결과**를 기준으로 처리한다. 음식 이름 같은 특정 단어, 검색 결과 개수, BM25·벡터 점수는 차단 기준으로 사용하지 않는다. 자료가 검색됐더라도 저녁 메뉴를 골라 달라는 요청은 범위 밖이고, 자료가 없어도 일반 CS 개념 설명은 허용한다.

| 원하는 결과 | 질문 예시 | 처리 |
| --- | --- | --- |
| 나의쿠키 이용 또는 공개 자료 탐색 | “전공노트는 어디에서 봐?” | 사이트 질문으로 답한다. 서비스 사용법을 뒷받침할 자료가 없으면 제보 메뉴를 안내한다. |
| CS·프로그래밍 설명 | “맛집 앱에서 가까운 가게를 찾으려면 DB 인덱스를 어떻게 설계해?” | 개발 질문으로 답한다. 사용한 자료에는 번호를 붙이고 일반 CS 지식만으로 설명할 때는 인용을 생략한다. |
| 일상 추천 등 범위 밖 결과 | “CS 공부 중인데 오늘 저녁 뭐 먹을까?”, “강남 맛집 추천해 줘” | 범위 밖으로 분류하고 고정 안내를 반환한다. |
| 대상이 모호함 | “추천해 줘” | 학습 주제나 사이트 메뉴를 구체적으로 물어본다. 다음 입력은 독립 질문이므로 주제와 요청을 함께 적으면 된다. |
| 여러 목적이 섞임 | “교착 상태를 설명하고 저녁 메뉴도 골라 줘” | 허용된 부분인 교착 상태만 설명하도록 지시한다. |

서버는 기존 순서대로 한도를 확인해 1회를 차감하고 공개 자료를 검색한다. 이후 Gemini에 질문과 자료를 전달해 **한 번의 답변 생성 요청**에서 의도와 답변을 JSON으로 받는다. 범위 밖이거나 모호하다고 분류되면 모델이 작성한 본문을 폐기하고 서버가 정한 문구를 반환한다. 의미 검색이 활성화되면 질문 임베딩 API 호출도 발생한다. 이 방식은 사용자가 받을 답변을 제한하며, 판정 전 검색 비용과 일일 횟수는 발생한다.

| `POST /api/v1/chatbot/ask` 응답의 `status` | 사용자 화면 |
| --- | --- |
| `ANSWERED` | 사이트 또는 CS 답변과 기존 근거 표시를 보여 준다. |
| `OUT_OF_SCOPE` | “쿠키 도우미는 나의쿠키 이용과 CS 공부를 도와드려요. 찾고 싶은 학습 자료나 궁금한 CS 개념을 물어봐 주세요.” |
| `CLARIFY` | “어떤 도움이 필요하세요? 찾고 싶은 학습 주제나 나의쿠키 메뉴를 알려 주세요.” |
| `UNAVAILABLE` | “지금은 답변을 생성하기 어려워요. 잠시 뒤 다시 시도해 주세요.” 모델 호출 실패, 알 수 없는 분류값 또는 읽을 수 없는 응답일 때 사용한다. |

위 네 상태는 HTTP 200과 남은 개인 한도(`remainingToday`)를 반환한다. 안내·재질문·장애 응답에서는 `sources=[]`, `grounded=false`이며 화면에는 근거 배지를 붙이지 않는다. 한도 소진은 기존처럼 HTTP 429로 처리한다. 의도 분류는 모델 판단이므로 오분류할 수 있다. 개발 서버에서는 위 질문들을 쌍으로 보내 분류 결과와 화면 문구를 확인한다. 기존 Hit@5는 자료 검색 지표이므로 이 정책의 차단 성공률을 측정하지 않는다.

## 5. RAG 설계 (정확도를 올리는 방법)

### 5-1. 검색 대상 (공개된 것만)
| 자료 | 위치 | 분량 |
| --- | --- | --- |
| CS 학습 문서 | `backend/src/main/resources/content/**` | 109개 |
| 웹 필수지식 | `frontend/src/data/webEssentials.js` | 57개 |
| CS 노트 | `frontend/src/data/csNotes.js` | 18개 |
| **서비스 안내 문서 (새로 작성)** | `backend/src/main/resources/chatbot/guide/*.md` | 10~15개: 메뉴 안내, 등급과 승급, 순위, 대결, 문제집과 풀이 기록 동기화, 계정과 소셜 로그인, 결제, 이메일 구독, 제보, 자주 묻는 질문 |
| 최근 패치노트 | `frontend/src/data/patchNotes.js` | 최근 5개 버전 |

- 화면 데이터(js)는 기존 `export-duel-bank.mjs`처럼 빌드 시 백엔드용 JSON으로 내보낸다
- **비공개 문제집, 비공개 해설, 개발 일지, 찬웅 전용 자료는 절대 넣지 않는다.** 색인 시 출처 경로를 허용 목록으로만 받고, 테스트로 비공개 키가 섞이지 않았는지 확인한다
- 기업 필기 문제 본문은 넣지 않는다(시험 자료 보호)

### 5-2. 조각내기
- 마크다운 제목(##) 단위로 자르고, 800~1,200자를 넘으면 문단 단위로 다시 자른다. 앞뒤 150자 겹침
- 조각 앞에 `과목 > 문서 제목 > 소제목` 경로를 붙여 임베딩한다(짧은 조각도 문맥을 잃지 않게)
- 조각마다 `출처 종류, 문서 ID, 제목, 이동 주소, 내용 해시`를 저장

### 5-3. 임베딩과 저장 (홈서버 8GB 전제)
- 임베딩: Gemini 임베딩 API(`gemini-embedding-001`, 768차원). 로컬 모델 컨테이너를 띄우지 않는다
- 색인: 서버 시작 시 내용 해시를 비교해 **바뀐 조각만** 다시 임베딩한다. 전체 색인은 약 1,000조각 이하, 하루 한 번 이하
- 저장: PostgreSQL 표 `chatbot_chunks`(본문, 메타데이터, 해시, 임베딩 `real[]`)에 저장하고, 서버 메모리에 올려 코사인 유사도를 계산한다
  - 1,000조각 × 768차원 기준 약 3MB. 새 컨테이너나 DB 확장이 필요 없다
  - pgvector는 조각이 수만 개로 늘 때 검토한다(지금 쓰는 `postgres:18-alpine` 이미지에 확장이 없어 DB 이미지 교체가 필요하기 때문)

### 5-4. 검색 방식과 선택 근거 (PR #210 구현)

1. **키워드 검색(BM25)**은 질문과 문서 조각의 제목·본문을 같은 규칙으로 나눈다. 연속된 한글은 두 음절씩 겹쳐 자른다(바이그램). 예를 들어 `쿠키를`과 `쿠키가`는 `쿠키`를 공유한다. 단독 한 음절은 그대로 두고 영문·숫자는 연속된 문자열을 사용한다. BM25는 일치한 검색 단위의 조각 내 빈도, 전체 조각에서의 희소성, 조각 길이로 점수를 계산한다.
2. **의미 검색**은 Gemini 임베딩으로 질문 전체와 문서 조각을 벡터로 표현해 의미가 가까운 조각을 찾는다. 임베딩 준비 전이거나 질문 임베딩 호출에 실패하면 BM25만 사용한다.
3. **RRF(Reciprocal Rank Fusion)**는 두 검색에서 각각 점수가 양수인 상위 20개 조각의 순위를 합산한다. 합산 순위대로 서로 다른 출처를 최대 5개 골라 답변 모델에 전달한다. 동의어 사전과 서비스 안내 가중치는 초기 설계의 후보로 남아 있다. [검색 구현](../backend/src/main/java/com/csstudy/backend/chatbot/HybridIndex.java)

#### 같은 표기가 여러 뜻일 때

“브라우저 쿠키를 어떻게 삭제해?”와 “초코 쿠키를 어떻게 구워?”에서 `쿠키`는 BM25 색인의 같은 항목을 조회한다. BM25에는 뜻별 식별자가 없다. 질문 전체로 보면 `브라우저`, `삭제` 등에서 나온 다른 검색 단위도 점수에 기여하므로 결과 순위는 달라질 수 있다. 형태소 분석기를 쓰면 명사와 조사를 나눌 수 있지만, 두 문장에서 모두 명사인 `쿠키`의 의미를 구별하려면 문맥이 필요하다.

Gemini 임베딩은 문맥에 가까운 문서를 별도로 찾아 순위를 보완한다. 질문이 “쿠키?” 한 단어뿐이면 의도는 여전히 모호하다. “초코 쿠키를 어떻게 구워?” 같은 질문도 검색 결과를 얻을 수 있다. 검색 후 4-1절의 기준에 따라 범위 밖으로 분류되면 서버는 검색 결과를 숨기고 고정 안내문을 반환한다.

| 방식 | 해결하려는 문제 | 쿠키 도우미에서의 판단 |
| --- | --- | --- |
| 바이그램 BM25 + Gemini 임베딩 (채택) | BM25는 정확한 용어와 부분 일치를 찾고, 임베딩은 표현이 달라도 문맥이 가까운 자료를 찾는다. | 8GB 홈서버에 별도 검색 모델을 올리지 않고 운영할 수 있다. 의미 검색에는 외부 API 호출이 필요하다. |
| SPLADE | 모델이 문서에 없는 관련 어휘에도 가중치를 줘 질문과 문서의 표현 차이를 줄인다. | 한국어 바꿔 말하기를 현재 검색이 반복해서 놓칠 때 비교할 후보이다. 모델 추론 비용과 어휘 확장에 따른 색인 크기를 함께 측정해야 한다. [SPLADE 논문](https://arxiv.org/abs/2107.05720) |
| BM42 | 짧은 조각에서 단어가 한 번씩만 등장해도, 어텐션으로 조각 안의 단어 중요도를 추정하고 전체 자료에서의 희소성(IDF)을 반영한다. | 짧은 조각 사이의 순위를 개선하는지 실험할 후보이다. 개발사도 평가 오류 수정 후 공개 벤치마크에서 Tantivy BM25가 앞섰다고 보고했다. [Qdrant의 정정 및 평가 결과](https://qdrant.tech/articles/bm42/#benchmarks) |

공개 자료 503조각과 평가셋 113문항 중 정답 문서가 있는 88문항에서 BM25 단독 Hit@5는 85/88, 하이브리드는 88/88이었다. Hit@5는 정답 문서가 상위 다섯 출처 안에 들어온 비율이다. 이 결과가 현재 구성의 채택 근거이며, 동음이의어만의 정확도, 범위 밖 질문 거절률, 최종 답변 품질 및 SPLADE·BM42와의 우열은 별도 평가 대상이다. [평가 결과와 분모](ai-chatbot-eval.md)

### 5-5. 근거 판단과 답변 생성
- 상위 조각의 점수가 기준값보다 낮으면 🟡 일반 지식 모드로 답한다. 기준값은 평가셋으로 정한다
- 프롬프트에 조각을 `[1]~[5]` 번호와 함께 넣고, "자료로 답할 수 있는 문장 뒤에는 번호를 단다, 자료에 없으면 없다고 말한다"를 지시한다
- 응답에 번호가 하나도 없으면 배지를 🟡로 내린다(모델이 자료를 안 쓴 경우를 걸러냄)
- 모델: `gemini-2.5-flash`, temperature 0.2, 최대 출력 800토큰. 직전 대화 최대 6턴만 함께 보낸다

### 5-6. 정확도 평가 (완료 기준)
| 평가 | 데이터 | 1차 목표 |
| --- | --- | --- |
| 학습 질문 검색 | 기존 평가셋 113문항 | Hit@5 95% 이상, Hit@1 88% 이상(벡터만 쓴 86.4%보다 높게) |
| 서비스 질문 | 새로 30문항 | 정답 문서가 상위 3개 안에 90% 이상 |
| 자료 밖 질문 | 새로 25문항 | 🟢로 잘못 표시 5% 이하 |
| 답변 품질 표본 | 무작위 30개 사람 검토 | 사실 오류 0건, 출처 번호와 실제 내용 일치 |

- 평가 스크립트는 API 키가 있을 때만 수동으로 돌린다(`./gradlew chatbotEval`). CI에서는 키 없이 키워드 검색, 조각내기, RRF, 비공개 자료 제외만 테스트한다
- 결과는 `docs/ai-chatbot-eval.md`에 날짜와 함께 기록한다. 👎 비율은 관리자 화면에서 본다

## 6. 서버와 운영

### 6-1. API
- `POST /api/v1/chatbot/ask` 요청 `{message, history[]}` → 응답 `{answer, grounded, sources[{n, title, url}], remainingToday}`
- `POST /api/v1/chatbot/feedback` `{answerId, good, reason}` (집계만 저장)
- 옛 `POST /api/v1/chat`은 지운다

### 6-2. 한도와 비용 보호 (Gemini 무료 등급)
| 한도 | 기본값 | 저장 |
| --- | --- | --- |
| 비로그인 | 하루 10회, 분당 3회 | Redis(멈추면 메모리) |
| 로그인 | 하루 50회, 분당 5회 | Redis(멈추면 메모리) |
| 서비스 전체 | 하루 `CHATBOT_DAILY_TOTAL`회 | 넘으면 그날은 관련 문서 링크만 보여 주는 대체 응답 |

- Gemini가 429나 오류를 주면 사용자에게 "지금은 답하기 어려워요"와 함께 검색된 문서 링크를 보여 준다(검색은 동작하므로)
- 같은 질문이 짧은 시간에 반복되면 10분 동안 답변을 캐시한다

### 6-3. 개인정보와 로그
- 대화 내용은 서버에 저장하지 않는다. 화면은 브라우저 `sessionStorage`에 최근 대화만 보관
- 로그에는 질문 원문을 남기지 않고 길이, 근거 모드, 응답 시간만 남긴다
- 무료 등급은 입력이 서비스 개선에 쓰일 수 있으므로 창 머리에 "개인정보는 입력하지 마세요"를 항상 표시

### 6-4. 예외 (CookieErrorCode에 추가)
| 이름 | 상태 | 문구 |
| --- | --- | --- |
| `CHATBOT_DISABLED` | 503 | 지금은 쿠키 도우미를 쓸 수 없어요. |
| `CHATBOT_DAILY_LIMIT` | 429 | 오늘 질문 횟수를 다 썼어요. 내일 다시 물어봐 주세요. |
| `CHATBOT_MESSAGE_TOO_LONG` | 400 | 질문은 500자까지 쓸 수 있어요. |

### 6-5. 환경변수 (`.env.example`, `docker-compose.yml`에 함께 적기)
| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `GEMINI_API_KEY` | (이미 있음) | 비어 있으면 챗봇 버튼을 숨긴다 |
| `CHATBOT_ENABLED` | `true` | 끄면 버튼과 API를 닫는다 |
| `CHATBOT_MODEL` | `gemini-2.5-flash` | 답변 모델 |
| `CHATBOT_EMBED_MODEL` | `gemini-embedding-001` | 임베딩 모델 |
| `CHATBOT_DAILY_GUEST` / `CHATBOT_DAILY_USER` / `CHATBOT_DAILY_TOTAL` | `10` / `50` / `500` | 하루 한도 |

### 6-6. 자원
- 새 컨테이너 없음. 백엔드 메모리 증가는 수십 MB 이내로 예상(조각과 임베딩 약 3MB, 키워드 색인 포함). 배포 전 스테이징에서 `docker stats`로 확인
- 응답 시간 목표: 검색 300ms 이내, 전체 p95 8초 이내(Gemini 응답 시간 포함)

## 7. 작업 순서
1. 서비스 안내 문서 10~15개 작성(챗봇 정확도의 기반)
2. 색인: 조각내기, 화면 데이터 내보내기, Gemini 임베딩, `chatbot_chunks` 저장, 비공개 제외 테스트
3. 검색: 벡터, BM25, RRF, 동의어 사전. 평가셋으로 Hit@k 측정 후 기준값 결정
4. 답변: 프롬프트, 인용 번호 검사, 근거 배지, 한도, 예외
5. 화면: 열기 버튼, 대화 창, 출처 칩, 배지, 피드백, 모바일, 다크 모드
6. 옛 카오스 고양이 코드 제거, 스테이징에서 평가와 메모리 확인, 결과 기록 후 운영 배포
