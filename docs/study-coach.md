# AI 학습 코치 · 첫 버전

진입: 상단 첫 메뉴 및 메인 `오늘 뭐 공부하지?` → `/study-coach`.

시험 유형, 날짜, 하루 공부 시간, 선택적인 약한 과목을 입력한다. AI는 시험 유형·남은 일수·시간만 받아 과목 순서와 학습 방향을 제안한다. 개인 정보, 자유 입력, 학습 기록은 외부로 보내지 않는다. 화면은 주제별 문제집의 기록을 사용해 약한 과목, 오답, 미풀이 문제를 우선 배치한다. 추천 콘텐츠는 기존 문제은행 ID만 사용하며 답과 해설은 기존 콘텐츠를 표시한다.

## 현재 범위와 한계

- 백엔드 필기, 금융권 IT 필기, 컴퓨터일반, CS 면접 기초, 데이터·AI 기초. 특정 기업의 실제 공고/출제 범위를 자동 수집하지 않는다.
- 과목별 노트 연결, 화면 내 객관식 풀이, 오답 해설, 복습 완료, 결과 반영 재계획.
- 계획/완료 상태는 브라우저에 계정 ID별 저장. 계획 자체의 기기 간 동기화는 아직 없다. 풀이 기록은 기존 `topics` 동기화를 사용한다.
- 약점 분석은 주제별 문제집 기록 범위이다. 모든 문제은행/노트 완료 기록을 통합 분석하지 않는다.
- Gemini structured output 기반 과목 우선순위 추천이다. 자율 도구 호출 또는 다중 에이전트 구현이라고 소개하지 않는다.
- 키/할당량/모델 오류는 명시적으로 실패를 표시. 사용자가 `기본 계획`을 선택하면 규칙 기반 계획으로 진행한다. AI 성공으로 위장하지 않는다.
- 해커톤 시연에는 가상 사용자와 직접 작성/이용 가능한 콘텐츠를 사용한다.

## 운영

기존 `GEMINI_API_KEY` 재사용. `STUDY_COACH_MODEL` 기본값 `gemini-flash-lite-latest`, 홈서버 compose 전달. AI 계획은 서버 로그인 검증, 계정당 시간당 15회·5초 간격, 동시 처리 2개. 외부 응답 제한 30초, 출력 enum·중복·범위·길이 검증. 키/입력/응답을 로그에 기록하지 않는다.

배포는 feature → dev → master 순서. 실제 운영의 모델 호출 성공 여부는 키가 설정된 서버에서 별도 확인해야 한다. 모의 API 성공 테스트는 실제 Gemini 품질 평가를 대신하지 않는다.

## 검증

`npm run check:study-coach`, `npm run lint`, `npm run build`, `gradlew test --tests '*StudyCoachServiceTest'`.
브라우저에서 기본 계획 생성, 문제 3개 정오답 처리, 해설 확인, 완료 체크, 새로고침 후 완료 유지 확인.
