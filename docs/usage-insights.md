# 관리자 이용 분석

관리자 모니터링의 첫 탭 ‘이용 분석’에서 기존 `/admin/usage`와 `/admin/reports` 자료를 사용한다. 관리자 인증·권한을 유지하며 새 공개 집계 API나 DB 스키마를 만들지 않는다.

- 클릭: 선택 기간의 `clicks[].range`로 정렬한다. 누적 클릭과 누적 고유 방문자(`visitors`)를 선택 기간 지표에 섞지 않는다. 노출 계측이 없으므로 CTR을 계산하지 않는다.
- 페이지: 기존 API의 조회 상위 최대 20개다. 조회수/해당 페이지 고유 브라우저 수를 반복 열람 지표로 표시하고 분모가 0이면 ‘—’로 표시한다.
- 개선 검토: 조회 20회 이상·브라우저당 조회 3회 이상이라는 내부 검토 규칙이다. 재학습과 새로고침도 포함하므로 오류·불만·이탈 판정에 쓰지 않는다. 제보의 미처리 건수는 전체 기간 지표로 구분하고 제보 탭으로 이동한다. 제보 조회 실패는 0건과 구분한다.
- 풀이 완료: 기존 `exam` 이벤트 수다. 클릭이나 조회를 분모로 완료율을 만들지 않는다. 세션 이탈률·체류 시간·만족도는 현재 수집하지 않는다.

클릭 계측은 배포 이후부터 주요 공개 화면 사이의 링크와 명시한 면접 동작(녹음 시작/종료 클릭, 랜덤 질문, 답안 확인)에 한정한다. DOM 글자나 입력값은 읽지 않는다. 같은 출처의 허용된 경로만 사용하며 쿼리·해시·계정/프로필/비공개 경로와 외부 링크를 보내지 않는다. 녹음 시작 클릭은 권한 허용이나 녹음 성공을 뜻하지 않는다. 페이지 조회는 기존 계측을 유지한다.

신규 클릭은 기본 링크 이동과 실행 버튼의 동작 전에 capture 단계에서 기록한다. 요청 실패는 기존 track 함수처럼 사용자 흐름에 영향을 주지 않는다. 기존 관리자 화면의 기간(7/30/90일), 새로고침·자동 갱신을 따른다. 분석을 위해 원시 로그나 개인정보를 추가 노출하지 않는다.

참고: [Google Analytics 지표 정의](https://support.google.com/analytics/table/13948007?hl=en-EN), [NN/g 연구 방법 구분](https://www.nngroup.com/articles/which-ux-research-methods/). 세션·노출·정성 조사가 필요한 지표를 단순 클릭 수와 구분한다.

검증: `npm run check:usage-insights`, 전체 ESLint, 빌드, 기존 헤더·면접·제보 관련 검사. 화면 검증은 실제 이용자 기록 대신 예시 자료로 진행한다.
