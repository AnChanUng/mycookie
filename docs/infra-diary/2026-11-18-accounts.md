# 인프라 일기 · 2026-11-18 · 클라우드 계정 정리 (Render · Neon)

> 캡처는 `docs/infra-diary/images/2026-11-18-accounts/`에 로컬로만 보관합니다(계정 정보가 보여 공개 저장소에 올리지 않음).

## 배경
운영 백엔드의 `APP_BASE_URL`을 mycookie.dev로 바꾸고 스테이징 DB를 붙이려고 Render · Neon 대시보드에 들어갔다.

## 1. Render 계정이 두 개였다
- 처음 로그인한 Render 계정의 `cs-study-backend`는 주소가 `cs-study-backend.onrender.com`. 사이트가 실제로 부르는 `cs-study-backend-i0ln.onrender.com`이 아니었다. → 01
  - 이 서비스는 저장소 기록에 없는 옛 커밋(Spring Boot 3.2 시절)으로 떠 있고, 시작할 때마다 DB 연결 실패(`PSQLException: The connection attempt failed`)로 종료. 우리가 master에 머지할 때마다 같이 배포를 시도하다 실패하고 있었다.
  - `render.yaml` 블루프린트 때문에 이 계정에도 스테이징 · `-21ay` 중복 서비스가 생겨 모두 배포 실패.
- 서비스 4개의 주소를 하나씩 열어 i0ln이 없음을 확인한 뒤, 다른 계정으로 로그인하니 i0ln 서비스가 있었다. → 02
  - 운영 `APP_BASE_URL`은 이미 `https://mycookie.dev`. `render.yaml` 변경이 블루프린트 동기화로 자동 반영돼 있었다.
  - 이 계정의 스테이징 서비스 주소는 `cs-study-backend-staging-zq0t.onrender.com`. 코드에는 접미사 없는 주소(=버려진 계정 서비스)가 적혀 있어 수정(AnChanUng/mycookie#51).
  - 운영에 `ADMIN_KEY`가 없어 관리자 API가 닫혀 있음(값이 없으면 닫히도록 설계).

## 2. Neon 계정도 두 개였다
- 처음 계정은 프로젝트 0개. → 03
- 다른 계정에 운영 DB `cs_study`(Singapore, 35MB, 브랜치 production 1개). → 04
- **스키마만 복사(Branch schema only)** 로 `staging` 브랜치를 만들었다. 운영 데이터는 복사되지 않는다. → 05
  - 함정: Neon 브랜치 생성 창의 Auto-delete 기본값이 **"After 1 day"**. 그대로 만들면 하루 뒤 사라진다 → Never로 변경.
  - 연결 문자열(비밀번호 포함)은 직접 입력하지 않는다.

## 3. 결정: 스테이징은 홈서버에서
- DB를 홈서버(PostgreSQL + Redis)로 옮길 계획이라 클라우드 스테이징 연결은 여기서 멈춤. Neon `staging` 브랜치는 비어 있고 쓰지 않으면 비용이 없어 보관.
- 홈서버 DB도 **PostgreSQL**로 결정: 운영 데이터를 pg_dump/pg_restore로 그대로 옮기고 코드 변경이 거의 없다. MySQL은 형식 변환 · 코드 수정 위험이 크다.
- 원칙: 기존 이용자 데이터는 전부 보존(운영 DB 전체 이전 + 검증 후 주소 전환).

## 남은 정리(확인 후 진행)
- 옛 Render 계정의 버려진 서비스(`cs-study-backend`, `-21ay`, 스테이징) 삭제 또는 정지
- 운영 계정의 `cs-study-backend-staging`은 DB 없이 떠 있어 무료 시간(계정당 월 750시간)을 쓸 수 있음 → 정지 검토
- 운영 `ADMIN_KEY` 설정 여부

## 4. 스테이징 서비스 정지 (추가)
- 운영 계정의 `cs-study-backend-staging`(zq0t)을 Settings → **Suspend Web Service**로 정지(확인 문구 입력). → 06
  - 이유: DB 없이 떠 있어 쓸모가 없고, Render 무료 시간은 계정 전체 월 750시간이라 운영 시간을 갉아먹을 수 있다.
  - 정지는 Resume으로 되돌릴 수 있다. 홈서버 스테이징이 생기면 삭제 여부를 정한다.
- 정지 후 확인: 대시보드 Active 2 · Suspended 2, 스테이징 503, 운영 백엔드 200(첫 요청은 잠에서 깨느라 약 36초), mycookie.dev 200.
