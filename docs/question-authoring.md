# 문제 출제 원칙

2026-11-24부터 새로 내는 문제와 해설은 **공식 문서를 근거로** 출제합니다. 사람이 쓰든 AI 에이전트가 쓰든 같습니다.

## 근거로 쓰는 자료

| 순위 | 자료 | 예 |
| --- | --- | --- |
| 1 | 공식 문서 · 표준 | Spring · Java(Oracle, JLS) · PostgreSQL · MySQL · Kubernetes · AWS 공식 문서, RFC, W3C · WHATWG 명세, OWASP |
| 2 | 공식 저장소 · 공식 블로그 | 프로젝트 GitHub 저장소의 문서 폴더, 공식 엔지니어링 블로그 |
| 3 | 보조 자료 | 교재, 기술 블로그, 강의. 1 · 2순위로 확인한 내용을 쉽게 풀 때만 쓰고 단독 근거로 쓰지 않습니다 |

- 버전에 따라 답이 달라지는 내용(예: Java 21 가상 스레드, HTTP/3, Spring Boot 3)은 문제나 해설에 기준 버전을 적습니다.
- 공식 문서 사이트에 직접 접속할 수 없으면 공식 Git 저장소의 같은 문서를 확인하고, 확인한 커밋을 남깁니다(`docs/web-essentials.md` 참고).

## 출처 남기기

- 문제 묶음을 만들거나 크게 고칠 때는 그 묶음의 문서(`docs/*.md`)나 PR 본문에 **확인한 공식 문서 링크와 각 링크로 확인한 내용**을 적습니다.
- 해설에 원문 링크 칸이 있는 데이터(예: 웹 필수지식의 원문 링크)는 공식 문서 링크를 넣습니다.
- 공식 문서와 다른 설명(관례, 실무 판단)은 해설에 "실무 관점"처럼 구분해서 적고, 공식 사실처럼 쓰지 않습니다.

## 예외

- **기업 필기 복기 · 기출 문제집**: 문제 자체는 복기한 내용을 따르고, 정답과 해설만 공식 문서로 확인합니다. 공식 문서로 정답을 확인할 수 없으면 해설에 그렇게 적습니다.
- **직접 만든 코드 문제(디버깅 · 코딩 테스트)**: 언어 동작에 관한 해설은 언어 명세나 공식 문서로 확인합니다.

## 기존 문제

이미 공개된 문제를 한꺼번에 바꾸지는 않습니다. 오류 제보를 받거나 해당 묶음을 고칠 때 이 원칙에 맞춰 근거를 보강합니다. 문제 ID와 이용자의 풀이 기록은 그대로 둡니다.
